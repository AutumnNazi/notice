# 时辰筏

`时辰筏` 是一个运行在 Windows 10 / 11 上的桌面提醒工具。它支持单次提醒、固定间隔提醒、按星期提醒、按月日提醒和 Cron 表达式提醒，提醒通过 Windows 原生通知中心发送。

当前仓库里的代码已经不是“需求草案”，而是可运行、可打包、可直接使用的版本。

## 当前交付

- 程序名称：`时辰筏`
- 默认提醒标题：`时辰有讯`
- 源码入口：`main.py`
- 最终可执行文件：`dist/时辰筏/时辰筏.exe`
- 本地数据目录：程序同级的 `data/`（源码运行时为项目的 `data/`）

## 直接使用

如果你只是要使用软件，而不是开发它，按下面方式操作即可：

1. 打开 `dist/时辰筏` 目录，保留整个目录及其中的 `_internal/`、`data/`。
2. 双击 `时辰筏.exe` 启动程序。
3. 点击主界面右上角的“新建提醒”。
4. 填写标题、正文和提醒时间后保存。
5. 等待 Windows 通知中心在触发时间发送提醒。

## 已实现功能

### 提醒触发方式

- 单次定时：指定具体日期和时间，只触发一次。
- 循环间隔：按固定间隔重复提醒，例如每 30 分钟、每 2 小时；各项不得为负数，总间隔必须大于 0。
- 按星期触发：选择周几，在固定时间提醒。
- 按月日触发：每年固定月日提醒，适合生日、纪念日。
- Cron 表达式：高级用户可以直接输入标准 5 段 Cron 表达式。
- 每周最后工作日：取每周最长连续工作段的最后一天，整周休假则跳过该周。

### 提醒内容

- 自定义标题
- 自定义正文
- 优先级：`普通` / `重要`
- 默认静默：当前版本不播放声音

### 任务管理

- 新建提醒
- 编辑提醒
- 删除提醒
- 启用 / 停用单条提醒
- 暂停全部提醒 / 恢复全部提醒
- 稍后提醒：在卡片菜单里选“10 分钟后再说”，到点补发一次通知，不改动提醒自身的周期与启用状态
- 稍后提醒发送失败时每 60 秒重试；删除、退出或新的补发安排会取消旧请求的重试，不覆盖新安排。
- 列表展示下次提醒时间
- 支持多条提醒并行运行
- 单次提醒经系统通知 API 接受后自动停用；发送失败每 60 秒重试，工作日提醒发送失败仍继续排下周；编辑配置失败时保留原调度。
- 发送前检查 Windows 通知是否被应用、用户或系统策略禁用；被阻止时按发送失败处理并重试，不提前消耗单次提醒。该检查不保证通知弹窗可见或用户已阅读。
- 已排程的单次、工作日和稍后提醒在暂停或休眠恢复后仍会执行；载入时已过期的单次配置仍自动停用。
- 暂停时已派发但尚未发送的单次与稍后提醒会留回队列，恢复后执行，不覆盖已有的新调度。
- 排队中的旧调度绑定原任务对象，编辑或重建同 ID 提醒后不会提前执行或停用新配置。
- 通知标题与正文通过标准输入传递 XML 数据，特殊符号不会被当作 PowerShell 代码，长正文不占用命令行空间；发送超时与失败写入运行日志。
- 任务和设置采用临时文件落盘后原子替换，写入失败不会覆盖原数据。
- 本地记录损坏时（间隔为负、触发方式无法识别等）只把该条降级为停用并保留原配置，可在界面上改好后重新启用，不影响同一文件里的其它提醒。
- 启用与声音字段必须是 JSON 布尔值；非法值会停用该条并记录原因，不会把字符串 `"false"` 当作启用。
- 非有限 JSON 数值与超长整数会留档并回退安全值；循环间隔超出可表示日期范围时只停用该条，不中断其它提醒排程。
- JSON 同一对象内的重复字段会留档并回退安全值，不会静默采用最后一个启用状态、时间配置或关闭选项。
- JSON 转义中的孤立 Unicode 代理字符会留档并回退安全值，避免读取成功却无法 UTF-8 保存；合法中文和 emoji 保持可用。
- 通知标题和正文拒绝 XML 不支持的控制字符，异常条目原文留档并停用；换行、制表符、中文和 emoji 不受影响。
- 循环间隔拒绝布尔值和带小数的数值，不会截断小数或让负小数绕过非负校验；既有整数字符串仍可读取。
- 按周、工作日和按年提醒校验时间范围与字段类型；不存在的月日会被拒绝，2 月 29 日仍可按闰年触发。
- 日历配置读取、编辑和排程共用校验；异常记录在自动保存前完整留档，修复后可重新启用。
- 单次日期与时间、Cron 表达式在读取时校验格式和类型；异常配置停用并留档，不影响同文件其它提醒。
- Cron 必须至少存在一次未来触发日期；无解日期组合会被拒绝，闰日和包含有效日期的月份组合仍可用。
- 错误星期字段仍可打开编辑器修复，展示时只勾选合法星期；单次提醒的显式时区按该时区比较是否过期。
- 未知或错误类型的优先级回退普通，异常容器值不会阻止提醒编辑保存。
- 后台提醒状态保存失败时仍刷新界面并自动重试，用户主动编辑的保存失败仍按事务回滚处理。

### 实时信息

- 时钟每秒刷新，跨日后提醒卡片的“今日／明日”也会同步变化

## 日常使用说明

### 新建提醒

1. 点击“新建提醒”，或按 `Ctrl+N`。
2. 在“提醒内容”里填写标题和正文。
3. 在“提醒时间”里选择触发方式。
4. 根据触发方式填写具体时间参数。
5. 点击“保存提醒”。

### 编辑提醒

- 在列表中选中一条提醒，点击“编辑选中项”。
- 或直接双击列表中的提醒行。

### 删除提醒

- 选中提醒后点击“删除选中项”。

### 启用或停用提醒

- 选中提醒后点击“停用/启用”。

### 暂停全部提醒

- 点击“暂停全部提醒”后，所有提醒暂停调度。
- 再次点击可恢复。

### 稍后提醒

- 点击提醒卡片右侧的“⋮”，选择“10 分钟后再说”。
- 到点会再补发一次通知，**不会**改动这条提醒自己的周期，也不会消耗单次提醒。

### 设置

- 点击主界面中的“设置”。
- 可以修改字体、导入字体目录、设置开机启动、设置关闭按钮行为。

## 关闭行为说明

点击窗口右上角关闭按钮时，程序会按设置决定行为：

- `每次询问`：每次点关闭都弹窗确认。
- `缩小到托盘`：窗口隐藏到托盘，程序继续后台运行。
- `直接关闭`：程序彻底退出。

如果你在关闭提示框里勾选“记住这次选择”，以后会直接执行该行为。

### 运行日志

```text
data/logs/notice.log
```

出问题时先看这里：警告与异常会带时间戳记进来，单个文件满 1 MB 自动轮转，最多保留 3 份。
按钮与定时界面回调异常也会记录完整堆栈，不依赖可见控制台。
未捕获的后台线程异常也会记录线程名与完整堆栈，正常线程退出不作为崩溃记录。
日志目录不可写时自动降级为只输出到控制台，不会因为写不了日志而影响使用。

### 数据文件损坏时的副本

```text
data/tasks.json.corrupt-YYYYmmdd-HHMMSS
data/settings.json.corrupt-YYYYmmdd-HHMMSS
```

数据文件整体读不动时（内容不是合法 JSON 等），程序会照常启动，并把坏的那份**原样复制**成
上面这个名字留档，原文件本身不动，方便你自己翻回来找内容。同一份坏内容只留一份副本。
同一秒出现不同损坏内容时，备份名追加序号，不覆盖已有副本；写入失败会清理本次不完整副本。
逐条容错跳过或降级提醒时也先保留完整原文。若备份失败，程序仍能启动，但保存会先重试备份，成功前不覆盖原文件。

## 使用注意事项

- 提醒与语录本地运行；天气需要联网，优先使用 Windows 定位服务，农历使用 Windows 本地日历。信息服务不可用时显示失败提示并重试，不影响提醒调度。
- Windows 可能会对新生成的 `.exe` 弹出 SmartScreen 提示，需要手动允许运行。
- 如果修改了通知名称、图标或快捷方式后发现系统通知显示仍旧异常，通常重启一次程序即可刷新。
- 如果旧版本 `时辰筏.exe` 仍在运行，重新打包时可能无法直接覆盖，需要先退出旧进程。
- 字体目录导入的是本机可用字体，目录里需要包含 `.ttf` 或 `.otf` 文件。
- 字体目录扫描或单个字体注册失败时只跳过失败项并记录日志，其它字体仍继续加载；更新广播失败不撤销已注册字体。
- 同进程重复导入已注册字体不会重复注册或广播，选择器仍可使用；失败文件可重试，新增字体可继续加载，同路径字体替换后需重启程序。
- 过去时间的“单次提醒”不会继续调度，程序会自动视为过期。
- 提醒数据里有读不通的内容时，程序不会打不开：那条提醒会保留下来并自动停用，界面上标成待修复，你改好触发条件再启用即可；同一份数据里其它正常的提醒不受影响。
- 重复、空值或占用稍后提醒前缀的任务 ID 会重新分配，保留记录并停用异常条目，原因写入日志。
- 启动异常、取数失败这类问题会记进 `data/logs/notice.log`，反馈问题时附上这个文件最有用。
